1 · Publishing steps

Total cost to launch ≈ $130 (+$99/yr Apple). The critical path is account verification — start Phase 0 and the store signups immediately.

PHASE 0 Company prerequisites — week 1, everything in parallel

  1. YOURegister the Azerbaijan MMC via e-taxes.gov.az (ASAN İmza ~18 AZN; e-registration free; ~3 business days; no minimum capital). The MMC unlocks organization accounts on both stores — avoiding Google's 12-tester rule and keeping your personal name off the listing.
  2. YOURight after registration, apply for the KOBIA startup certificate (smb.gov.az) — 3-year profit-tax exemption on innovation income; confirm scope with your accountant.
  3. YOURequest a D-U-N-S number via Apple's free flow (developer.apple.com/enroll/duns-lookup) — allow up to 30 days, usually faster.
  4. YOUOpen a company bank account (ask for USD too — Google pays out in USD).
  5. DEVFill the legal placeholders (docs/legal/README.md lists them: legal name, VÖEN, address, effective date), then node scripts/generate-legal-content.mjs and redeploy the landing site.
Fallback if shipping before the MMC exists: Apple individual enrollment (personal name shows as seller) + Google personal account — but the personal Google account requires a closed test with 12 testers opted in for 14 continuous days before production.

PHASE 1 Store accounts — week 1–2

  1. YOUGoogle Play Console — organization account under the MMC, $25 one-time. Also set up the merchant/payments profile now (Azerbaijan supported; USD payouts).
  2. YOUApple Developer Program — organization enrollment, $99/yr, needs the D-U-N-S. If org enrollment stalls from Azerbaijan, enroll as individual and migrate later.
  3. YOUSentry (free tier): org axtaris, project axtaris-app. DEV Put the DSN in eas.json as EXPO_PUBLIC_SENTRY_DSN + set SENTRY_AUTH_TOKEN as an EAS secret. Crash reporting is already wired and inert until the DSN exists.

PHASE 2 Push credentials — 30 minutes, blocks every store build

The entire push pipeline (tokens → DB triggers → edge function → Expo) is built and deployed. Only credentials are missing — and Android builds now fail until google-services.json exists (deliberate forcing function).
  1. YOUconsole.firebase.google.com → Add project "AxtarIS".
  2. YOUAdd app → Android, package az.axtaris.app → download google-services.json → DEV place at repo root and commit (it holds no secrets).
  3. YOUFirebase → Project settings → Service accounts → Generate new private key. Never commit this.
  4. DEVnpx eas credentials -p android → upload the key as the FCM V1 credential.
  5. DEVRe-sync the push secret to one value: openssl rand -hex 32 → npx supabase secrets set PUSH_SECRET=… → same value into Vault (vault.update_secret in the SQL editor).
  6. DEVAfter the Apple account exists: npx eas credentials -p ios → EAS creates the APNs key.
  7. Verify on device: install fresh build → sign in → token appears in profiles → chat message from second account (backgrounded) → push arrives → tap opens the chat. Repeat foregrounded and from killed state.

PHASE 3 Listing assets & metadata — week 2

  • Screenshots: Android 1080×1920; iOS 6.7" (1290×2796) + 6.5". Set: home/recommendations, vacancy detail with match explanation, profile builder, chat, employer dashboard. Play also needs a 1024×500 feature graphic + 512² icon.
  • Copy: short (80) + full (4000) descriptions, Apple subtitle (30) + keywords (100). Azerbaijani first; use the app's own locale vocabulary.
  • Forms: Play Data Safety + Apple App Privacy answers are pre-drafted in RELEASE_CHECKLIST.md §6 and match the code. Privacy policy URL: axtaris.app/legal/privacy · Account deletion URL: axtaris.app/legal/delete-account (both live).
  • YOURotate the seed-account passwords first (hr@azercell.com / ali@example.com — a formerly-committed password is still live), then create clean candidate + employer demo accounts for review notes.

PHASE 4 Builds & submission — week 2–3

  1. DEVGates: tsc + jest green, npm run supabase:verify, migrations fully applied.
  2. DEVnpx eas build -p android --profile production (autoIncrement is on; the old 8/7 AAB is obsolete — no FCM baked in).
  3. DEVnpx eas build -p ios --profile production — first run is interactive for credentials.
  4. Play path: Internal testing → Closed testing (a handful of real users, ~a week) → Production at 20% staged rollout.
  5. Apple: npx eas submit -p ios → TestFlight → App Review. Review notes: demo accounts + "all payments disabled — free during beta".
  6. Review-risk answers (already mitigated in code): no digital purchases sold; UGC has report + block on chat/vacancies/companies/profiles; account deletion in-app + web; don't ship iOS without the APNs key uploaded.

PHASE 5 Post-approval

  • Staged rollout → 100% over ~3 days if crash-free rate holds (Sentry + Play vitals).
  • Flip the landing site's store links from "Tezliklə" to real URLs (landing/src/config/site.ts) and redeploy.
  • Register the personal-data information system on e-gov (required by the AZ personal-data law).

2 · Payment architecture

Full analysis with sources: docs/payments/payment-system-analysis.md. CEO summary (AZ) is its own page.

The decision: Employer B2B → Paddle web checkout on the landing site (merchant of record; accepts Azerbaijan sellers, even pre-incorporation). Candidate consumer → RevenueCat in-app purchases at 15% (Small Business Program) — mandatory anyway, since Azerbaijan's iOS storefront allows no external payment links. Phase 2: Payriff/epoint AZN checkout locally.
ChannelProviderTake rateWhy
Employer plans ($19/$49)Paddle (web)5% + $0.50MoR handles global VAT, invoices, chargebacks; Slack/Zoom pattern is store-compliant when the app shows no purchase UI
Candidate plans ($5/$15)RevenueCat + IAP15%Apple 3.1.1 mandates IAP for in-app-consumed subscriptions outside US/EU link-out regimes; Google similar until Sept 2027
AZ mass market (phase 2)Payriff / epoint~2–3%AZN cards, local trust, avoids the 18% bank-withholding trap on foreign B2C payments (from Sept 2026)
Rejected: Stripe direct——No Azerbaijan support; requires a foreign entity + self-managed tax
Fallback: Polar.shMoR5% + $0.50Pre-vetted backup if Paddle onboarding fails; AZ payouts confirmed
  • Entitlement sync: Paddle webhook + RevenueCat webhook → two Supabase edge functions → one subscriptions row per (user, audience) → the existing entitlements.ts module stays the single source of truth. Idempotency on provider event id; grace status on billing issues; the DB applications-per-day constraint stays coordinated with plan changes.
  • Compliance line in the app: login-gated unlocks always; no web-checkout links, prices, or steering anywhere in-app (outside the US storefront); candidate IAP is the only purchase UI.
  • Timeline: ~4–6 weeks of integration once store accounts exist; Android web-link checkout re-opens Sept 30 2027 (Epic settlement) — revisit fees then.
